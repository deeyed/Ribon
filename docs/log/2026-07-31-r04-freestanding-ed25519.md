# R04 freestanding Ed25519 provider 구현 기록

## 구현

R04는 generic signature provider ABI와 Monocypher 4.0.3 기반 production Ed25519 provider를
추가했다. Official release의 core, optional Ed25519 source, header와 license는 byte-for-byte
보존하고 Ribon wrapper에서 canonical `A`/`R`, low-order point와 exact-size input을 fail closed한다.

R18 product manifest는 provider class/ID/symbol을 선택하고 generated registry는 exact source
manifest digest와 provider pointer를 함께 낸다. Validation product는 232-byte product-bound
message를 만들고 실제 provider로 signature를 검증한다. Host-only OpenSSL signer는 RFC 8032 test
seed로 deterministic artifact를 생성하지만 seed, signer와 upstream signing entry는 final target
image에 남지 않는다.

기존 합성 artifact hash는 real Ed25519 envelope로 hard cut되어
`11a7469483b138193ec66ecb925a59d446f8661983a2c79560b67df38308881b`가 됐다.

## 검증 결과

- Provider unit: RFC 8032 2개, OpenSSL cross-tool 1개, single-byte mutation 328개, strict hostile
  point/scalar rejection
- Sanitizer: AddressSanitizer와 UndefinedBehaviorSanitizer 통과
- Freestanding compile-only: AMD64, AArch64, RISC-V64
- Product closure: 세 target 모두 production provider 선택, verify symbol 존재, signer/private
  seed/fixture provider 부재
- R18 deterministic rebuild: 두 signed artifact byte-for-byte 동일
- QStar graph의 generic signature/provider 분리와 provider unit/security graph suite 통과
- Documentation quality, Sphinx warnings-as-errors와 Doxygen/Breathe gate 통과

## 증거 경계

이 기록의 cryptographic 증거는 host unit/cross-tool, sanitizer, 세 architecture compile-only와 QEMU
validation이다. Key ID authority, mode/usage/revocation policy, protected rollback counter, production
private-key custody와 physical hardware는 실행하지 않았다. Monocypher 4.0.3의 upstream timing
범위를 넘어 Ribon 전체의 side-channel resistance를 주장하지 않는다.
